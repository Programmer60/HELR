# Codebase & Results Tour

This guide explains the repository structure, what each directory contains, and how the data flows from raw MIMIC-III CSVs all the way to final Homomorphic Encryption (HE) benchmarks. Use this document to easily understand the codebase and explain the experimental flow to others.

---

## 1. `preprocessing/` Directory
**Purpose:** Handles the raw, messy clinical data and turns it into a clean, machine-learning-ready cohort.

*   **`build_mimic3_dataset.py`**: The heavy-lifter. Since MIMIC-III is too large to fit in memory, this script uses **chunked reading** to process `CHARTEVENTS` and `LABEVENTS`. It filters for our approved `ITEMID`s, applies physiological plausibility bounds (e.g., removing impossible heart rates), and isolates data to the first 24 hours of admission.
*   **`mimic3_aggregated_features.csv`**: The output of the preprocessing step. A clean, tabular dataset containing 49,303 adult admissions with features aggregated (e.g., min, max, mean).

---

## 2. `baseline/` Directory
**Purpose:** Contains all the experimental scripts, executed sequentially in "Phases". This is the core logic of the research.

*   **`train_mimic3_lr.py`**: Trains the initial plaintext Logistic Regression baseline to establish our target accuracy and ROC-AUC.
*   **`feature_selection.py`**: Compares Random Forest vs. Logistic Regression coefficient magnitude to shrink the feature space. Identifies the "LR Top-10" features used to optimize HE runtime.
*   **`phase12_he_export.py`**: Bridges the plaintext and encrypted worlds. It freezes the dataset, imputes missing values, scales features, and exports pure numpy arrays to the `he_ready` folder.
*   **`phase3_poly_fit.py`**: Analyzes the logit distribution (the decision scores before the sigmoid) and mathematically fits custom Degree-3 and Degree-5 polynomials specifically for this clinical dataset over the `[-6, 6]` range.
*   **`phase5_full_circuit_validation.py`**: The cryptographic proof script. Uses TenSEAL to simulate a forward + backward pass, dynamically tracking the `coeff_modulus_size` to prove the `[60,40,40,40,40,40,40,60]` context perfectly fits the Degree-5 circuit with 1 level remaining.
*   **`phase7_scalability_full.py`**: The Dataset-Size experiment. Proves that changing $N$ (from 500 to 49,303) increases SIMD batches and runtime, but *does not* increase circuit depth.
*   **`phase8_feature_count.py`**: The Feature-Count experiment. Proves that changing the number of features (10 vs 15 vs 16) increases ciphertext counts and linear combination time, but *does not* increase multiplicative depth.
*   **`phase9_final_benchmark.py`**: The final 49,303-admission execution. Evaluates the full cohort homomorphically and generates the master results table.

---

## 3. `results/he_ready/` Directory
**Purpose:** The "airlock" between plaintext data engineering and Homomorphic Encryption.

TenSEAL and HE libraries operate on pure mathematical vectors, not pandas DataFrames. This directory contains the exact, frozen state of the data so the HE scripts have zero preprocessing overhead.
*   **`X_train.npy` / `X_test.npy`**: The final, normalized, imputed feature matrices (using only the selected LR Top-10 features).
*   **`y_train.npy` / `y_test.npy`**: The binary labels (1 = Ischemic Heart Disease, 0 = Otherwise).
*   **`weights.npy` / `intercept.npy`**: The fixed trained weights of the plaintext Logistic Regression model, ready to be encrypted or applied homomorphically.
*   **`mimic_polynomials.json`**: Contains the exact $C_0, C_1, C_3, C_5$ polynomial coefficients calculated in Phase 3.

---

## 4. `results/` Directory
**Purpose:** Contains all the final outputs, logs, tables, and graphs generated by the experiments in the `baseline/` directory.

### Key Output Files to Review:
*   **`master_experiment_table.csv`**: The holy grail of the project. A synthesized table combining the polynomial degree, dataset size, and feature count experiments to definitively prove how different variables scale in HE.
*   **`plaintext_vs_he_metrics.csv`**: Proves our predictive fidelity. Shows that Plaintext LR and HELR (Degree-5) achieve the exact same ROC-AUC (0.7257) on the held-out test set.
*   **`mimic3_full_he_results.csv`**: The raw timing and memory metrics for the final 49,303-admission encrypted inference (shows the ~4.2 second total runtime).
*   **`feature_selection_comparison.csv`**: Shows why we dropped 6 features (saving massive HE runtime) while only losing -0.0005 AUC.

### Key Graphs to Review:
*   **`final_runtime_scalability.png`**: Visually demonstrates the SIMD slot boundary at 8,192. You can clearly see the runtime "step" up as new ciphertext batches are required.
*   **`final_level_consumption.png`**: The most important cryptographic graph. It shows a perfectly flat line at "2 levels remaining" across all dataset sizes and feature counts, proving circuit depth is invariant to data volume.
*   **`final_feature_count.png`**: Shows how adding features linearly increases runtime (due to more Ciphertext-Plaintext additions) but leaves depth unchanged.

## 💡 How to Explain the Flow to Others
1.  **Start at `preprocessing`**: "We took massive, raw MIMIC-III hospital data and distilled it down to 49,000 clean admissions."
2.  **Move to `baseline` & `he_ready`**: "We didn't just encrypt blindly. We trained a plaintext model, threw away unhelpful features to save HE time, and froze the pure math arrays in the `he_ready` folder."
3.  **Explain the Polynomial**: "HE can't do sigmoid math. So we looked at our specific patient scores and fit a custom polynomial to safely approximate the sigmoid without crashing the cryptography."
4.  **Show the `results`**: "Finally, we ran experiments isolating dataset size, feature count, and polynomial degree. Our graphs definitively prove how HE scales, culminating in a 4-second encrypted inference over 49,000 patients."
